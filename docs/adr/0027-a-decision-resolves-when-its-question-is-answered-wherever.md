# A decision resolves when its question is answered, wherever

**Amended 2026-10-10 (ticket [#395](https://github.com/theagenticage/hercule/issues/395); decided in [#385](https://github.com/theagenticage/hercule/issues/385) and [#388](https://github.com/theagenticage/hercule/issues/388)):** the decision applies to Signals as well as Notifications ([ADR 0040](./0040-intake-holds-signals-notifications-are-hercules-own-messages.md)), with one change:

- **Signals follow it.** A Signal's status is `open | resolved`, and it resolves exactly once, as `decided` or `withdrawn`. There is no `handled`. A signal that ends on its source is the rule "answered wherever" applied to Signals ([spec 10 §9.6](../spec/10-triage-intake-and-notifications.md#96-when-a-signal-leaves)).
- **Snooze is allowed on Signals only**, as a per-user "hide until" ([spec 10 §9.7](../spec/10-triage-intake-and-notifications.md#97-snooze-and-not-urgent)). It is not an answer: the signal stays `open`, and its source is not told.
- **Expiry stays rejected.** A question still never ends because time passed.
- **Notifications keep no snooze.** Check-in has no Later view.
- **Intake's "since you last checked" marker is retired.** Intake is a list worked to empty, so it needs no marker of what is new.

A decision Notification's bound actions are one way to answer its question, not the only one: the same approval can be answered in the session view, the same breaker resumed from the Workflows screen, the same permission granted in Settings, and a question can stop existing altogether (the session ended, the token refreshed itself). Left alone, such records stay pending forever and the phone still shows live buttons. We decided the Notification has one status axis, `open | resolved`, and that a decision resolves exactly once, in one of three ways: **decided** when its question is answered anywhere (the core resolves its own kinds inside the operation that answers the question; sinks edit their messages as for a click), **handled** when an assistant holding a subscription covered it (created already resolved, pushed to no sink), or **withdrawn** when the question stops existing (the core for its own subjects; a plugin or session only for notifications it produced, with a one-line reason). Informational notifications are born resolved. Records are otherwise immutable - new facts are a new notification - and there is no per-record read state: no platform gives the controller a read receipt, so `readAt` could only ever mean "opened in the web app"; surfaces mark what is new with a per-view "since you last checked" marker instead. Rejected: an expiry or snooze concept (a stale question is either answered or gone, never merely old), notification-only resolution (forces the user back to the notification for something already done), and in-place updates by producers (a changed question is a different question). Ticket [#42](https://github.com/theagenticage/hercule/issues/42).
