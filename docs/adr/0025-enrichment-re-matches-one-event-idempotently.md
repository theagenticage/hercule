# Enrichment re-matches one event, idempotently

Events are matched at persist, but plugin-less systems (Sentry inside a Gmail-carried email) only become identifiable after a triage agent reads the content; under a never-re-dispatch rule, ref subscriptions and system filters would be permanently blind to them. We decided `event.enrich` (`system`/`url` overwrite, `refs` append-only) gives the matcher one more look at that single event in the same transaction: effect-row uniqueness absorbs everything that already fired, so only newly matching triggers and live subscriptions produce deliveries - re-match is not re-delivery, no consumer needs new idempotency, and the cursor never rewinds. Rejected: never re-matching (makes enrichment cosmetic) and full reprocessing (reopens every exactly-once guarantee). Ticket [#41](https://github.com/theagenticage/hercule/issues/41).
