# Secrets are encrypted per-value under a keychain-held master key

All secret values - Connection credentials, plugin KV secrets, runner-scoped secrets - live as rows in one owner-scoped secrets table in the controller database, each value encrypted under a master key held in the OS keychain (plain key file as the Linux/headless fallback); the SQLite file itself stays plain. This puts disk theft and backup/bundle leaks in the threat model: any copy of the database, including a promotion bundle, is useless without the master key, which never leaves its machine - promotion export re-encrypts the packed secrets under a key derived from the single-use promotion token, and the new controller re-wraps them under its own master key, satisfying the enumerable-and-extractable constraint from ADR 0005. Plaintext-at-rest was rejected because every OAuth token would leak with any DB copy; passphrase-on-start was rejected because it breaks unattended restart of an always-on controller; whole-database encryption (SQLCipher) was rejected because it encumbers every read path to protect mostly non-secret rows. Secrets never appear in the event log or API responses - references only.

Amendment (2026-08-28, spec assembly): the original text listed "runner credentials" among the encrypted rows. The runner's own credential is an opaque random token and, like every other token (ticket #18), is stored hashed on the runner record, not encrypted in this table; the `runner` owner kind stays reserved for runner-scoped secrets. See [docs/spec/13-security.md](../spec/13-security.md).

**Amended 2026-10-30 ([#406](https://github.com/theagenticage/hercule/issues/406)):** [ADR 0048](./0048-harnesses-and-provider-accounts-are-separate.md) replaces the owner kind `provider-instance` with `provider-account`, and a provider's secret names are `apiKey` and `token`. Because the owner kind, owner id and name are associated data, moving a value to its new owner is a decrypt and re-encrypt inside the migration, with the Master Key; if any value fails to decrypt, the migration fails and the boot stops on the pre-migration backup. The controller now also holds the Claude subscription token, which Hercule obtains by running `claude setup-token` on a runner.
