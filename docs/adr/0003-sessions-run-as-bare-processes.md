# Sessions run as bare processes on runners

Hydra's predecessor executed every agent session in a per-session Docker container (three locally-built image layers, generated Dockerfiles, docker-in-docker); v1 Hydra instead runs provider subprocesses directly on the runner, cwd'd into their workspace, on Linux and macOS only. The predecessor's own history argued for this: its container substrate accumulated unmanaged complexity (containers never reaped, security docs drifted from code, privileged mode silently dropped hardening exactly where isolation mattered most), its newest code path had already abandoned containers to spawn the provider CLI on the host, and its docs record credential-copy-into-sandboxes as a known mistake - OAuth refresh-token rotation wants credentials machine-local and referenced in place, which containers fight. Containers also invert the platform story on macOS, where Docker means a Linux VM that replaces the machine's real toolchains and Keychain. Isolation in v1 comes from provider-native mechanisms (Codex's sandbox, Claude Code's permission modes) plus Hydra's own approval flows; hydra-level native OS sandboxing (macOS Seatbelt, Linux Landlock) is deliberately post-v1 and designed to return as a probed runner capability behind the controller-runner capability negotiation, so the substrate gains a wrapper later rather than being rewritten. Containers remain a far-remoter option behind that same door.
