# Agents operate Hydra through the public API, behind one contract with two transports

Anything the user can do, an agent can do - through the same doorway. One framework-free service layer defines every operation; the API contract is a shared package of Zod input/output schemas that server validation, the `hydra` CLI, the web app, and the plugin public-API client all consume; HTTP routes are thin hand-written proxies over the service layer (schema-validate, call, serialize), and in-process consumers (built-in workflow actions, capability-granted plugins) call the same service layer directly. The parity guarantee is the contract, not the wire: nothing is reachable in-process that is not reachable over HTTP. OpenAPI is generated from the schemas. We deliberately deferred adopting an RPC framework (tRPC/oRPC/Effect RPC - t3-code uses Effect RPC with the same shared-contract-package discipline): the contract package is the expensive-to-retrofit asset and is pinned now; derivation machinery can be adopted post-v1 with empirical evidence, or never. Every mutation is stamped with an actor - the user, or `session:<id>` - in the existing event log; there is no separate audit subsystem, and multi-user later widens the actor field rather than restructuring.

Sessions reach the API via a runner-shipped `hydra` CLI (the same binary is the user's ops CLI, under a user credential instead): at session start the controller mints a token whose subject is the Session, the runner injects `HYDRA_API_URL`/`HYDRA_TOKEN` into the provider process, and the token dies with the session; resolution token -> session -> agent -> permission profile must not meaningfully add endpoint latency. We chose CLI over an MCP server for v1 (one artifact, uniform across providers, no per-adapter wiring; MCP stays high on the post-v1 list and the session spec keeps MCP passthrough) and teach it via one provider-agnostic skill source materialized per-provider - a minimal skeleton with progressive disclosure, the CLI self-documenting with agent-addressed help, static help plus 403s that name the missing grant. Parity is the ceiling, not the default: each agent carries a permission profile the token inherits, enforced at the service layer so it binds both transports (profile content and escalation live in the security model). All endpoints return fast; a spawn-type operation returns a handle and its response teaches the follow-up subscription command - there are no blocking waits, and the canonical long-wait pattern is start, subscribe (delivered as queued input on a turn boundary), end your turn.
