# Workflow actions may call the public API as the run

A pure "one external call per action, no host access" rule forces an LLM agent step for deterministic bookkeeping (static DAGs cannot fan out over data), and it was incoherent besides: a plugin holding the `public-api` capability may already mutate anything from its ingest loop, stamped and ungated. We decided action contributions receive `ctx.api`, a public-API client stamped `run:<runId>` with the `stepId` in the audit entry and a per-mutation summary on the step record; routing still reads declared outputs only (ADR 0008 intact), event emission from `execute()` stays forbidden (use the `event.emit` operation, which marks the event synthetic), and single-purpose actions remain the shipped convention. Watch in dogfooding: routing decisions leaking into `execute()` code. Ticket [#41](https://github.com/theagenticage/hercule/issues/41).
