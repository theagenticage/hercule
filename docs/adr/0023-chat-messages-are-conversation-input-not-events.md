# Chat messages are conversation input, not events

Every message a channel plugin observes in a bound Discord or Slack container is handed to the core's conversation service and stored as a conversation message keyed by container; none of it enters the persisted event pipeline that ADR 0009 makes the single path for external facts. We decided this because a chat line is input to an assistant, not a fact for triggers to match: nothing in v1 wants a workflow started by "someone said X in Slack" (that is what an assistant is for), the session transcript already records what the assistant was told, and the pipeline's shape is wrong for chat - a busy channel would put hundreds of dedup-keyed, trigger-matched, TTL-pruned events a day into the log to find two mentions, and the bounded unaddressed context an assistant needs at wake would have to be read back out of it. The alternatives were making every message an event (rejected for the volume and the mismatch just described) and a hybrid that emits a platform event only when an assistant is woken; the hybrid was not taken now but remains the additive path if chat-triggered workflows are ever wanted. Accepted cost: chat activity is not visible to triggers or to the events view, and audit of who told the assistant what lives in transcripts and the conversation table rather than in the event log.

**Note, 2026-10-10 (ticket [#395](https://github.com/theagenticage/hercule/issues/395); the map [#380](https://github.com/theagenticage/hercule/issues/380)):** the decision stands for messages in bound containers: they stay conversation input for the assistant, never events. A Slack **event source** may later sit beside the Slack **channel**, to raise Signals on Intake ([ADR 0040](./0040-intake-holds-signals-notifications-are-hercules-own-messages.md)). It emits events only for what it watches, such as a mention of the user or a DM to the user, never every message. The volume objection above does not apply, because the source watches a narrow set, not the whole channel. The Slack event source is not in v1.
