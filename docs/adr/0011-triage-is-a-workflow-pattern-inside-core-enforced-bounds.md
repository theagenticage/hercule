# Triage is a workflow pattern inside core-enforced bounds

Hydra has no triage engine. Deciding what matters is an ordinary workflow: a CEL trigger filter is the rules layer, a cheap agent step with a structured-output schema is the judgment layer, and graph edges route the verdict - the same blocks every other workflow uses, user-readable and user-editable. The recommended topology (convention, never enforced) puts triage at the only doorway between raw external events and expensive work: triage workflows trigger on external events and create or update Tasks; work workflows trigger on task platform events (`task.created`, `task.updated`). The core's contribution is mechanical: a per-trigger spawn bound (default ~30 runs/hour, per-trigger configurable) with breaker semantics - exceeding it auto-pauses the trigger, holds matched events visibly, and notifies the user, who resumes with one click (optionally discarding the backlog). Dropping excess would be silent loss; blind queueing just delays the stampede; a tripped breaker is itself the review moment where the user sees what almost spawned and fixes the filter. The exact-ref `task.query` built-in action (provenance refs, labels, status - identity matching, never content matching) enables the guard-before-agent pattern: duplicate signals route straight to `task.update` for pennies, which is what makes generous spawn limits affordable. We considered a dedicated core triage component (its config would duplicate what workflows already express, and "what matters" would end up buried in engine settings instead of an editable prompt), a marked triage workflow type for enforcement (core cannot tell triage from any other workflow without it becoming that engine), and other core bounds - a global concurrent-run cap (redundant: per-runner session caps already queue excess at placement), spend caps (unenforceable: subscription-auth providers report no reliable per-run cost; v1 displays cost, never gates on it), and quiet hours (pausing a workflow covers it). Accepted cost: nothing stops a user from wiring expensive work directly to raw events; the topology is protection by convention and shipped defaults, not by machinery.
