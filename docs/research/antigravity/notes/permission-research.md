## Main finding: the "edits run unasked" result was caused by /tmp
agy does not ask for edits under /tmp. Outside /tmp, `default` asks for every edit.
- /tmp workspace, `default`, edit outside the folder but under /tmp: no ask (rec2/mode-default.jsonl, mode-default-outside-tmp.jsonl, mode-default-outside-parentdir.jsonl).
- /tmp workspace, `default`, write /var/tmp/x.txt: asks write_file (rec2/mode-default-outside-vartmp.jsonl).

So the macOS recording (workspace in /tmp -> /private/tmp) asked, the Linux one (workspace in /tmp) did not: /tmp itself counts as always-writable on Linux. Cause inside agy not confirmed (guess: temp dir is exempt). Hercule workspaces live under the Hercule Home, not /tmp, so `default` should ask there. Hercule's tests must not use /tmp workspaces for approval checks.

## 2. Format and defaults
- Rule: `action(target)` string, no space before "(". Binary regex `^(command|read_file|write_file|read_url|mcp|execute_url|download_url|unsandboxed)\s*\(.*\)$`. Docs: "Each rule is an `action(target)` string" e.g. `command(git status)`, `read_url(github.com)`. deny beats ask beats allow (docs). Lists live under `permissions: {allow, ask, deny}`. `regex:` prefix opts into regex matching (changelog).
- My `permissions.ask: ["write_file(*)"]` in settings.json and in config.json did NOT make edits ask in `default` in a /tmp workspace (rec2/ask-settings.jsonl, ask-shared.jsonl; /tmp exemption may have hidden it; not retested outside /tmp).
- Settings (docs): `toolPermission` default "request-review", also "proceed-in-sandbox", "always-proceed", "strict" ("prompts before every tool action, including file reads, even if an allow rule matches"; "Deny rules apply in every mode"). `agentMode` default "auto" where available, else "". `allowNonWorkspaceAccess` default false. `trustedWorkspaces` default [].
- Changelog: URL fetch default changed from allowed to asking. In ACP the model has no read_url, only `search_web`, which ran unasked (rec2/mode-default-url.jsonl, mode-default.jsonl).
- ACP modes offered: default, accept-edits, plan (no auto) (session/new result in rec/basic-allow.jsonl).

## Route B: approval-required unsupported on Antigravity (read-only code reading)
Today's plugin declares approval-required native (plugins/antigravity/src/index.ts); this is what happens if it did not.
- Chain: packages/contract/src/access-modes.ts `findNearestSupportedAccessMode` walks DOWN from the requested mode; approval-required is the bottom, so it returns `undefined`. Spec 06 8.4: "If no equal-or-less-permissive supported mode exists, session start fails with a clear error."
- Thread or Agent start: apps/controller/src/daemon/sessions/placement.ts ~line 596: `Effect.fail(createInvalidStateError(\`${definition.displayName} supports no access mode at or below ${request.requestedAccessMode}\`))` -> "Antigravity supports no access mode at or below approval-required" (InvalidState). The start is refused, no session. Note the shipped default for `thread.accessMode` is approval-required (spec 14), so a default thread on Antigravity would fail until the user picks another mode.
- Assistant: apps/controller/src/daemon/sessions/live.ts ~line 449 (resume of a conversation session) fails with the same text; the doc comment at apps/controller/src/assistants/sessions.ts line ~59 says `give` can fail with InvalidState for it.
- Menu: packages/client-core/src/threads/access-modes.ts `buildAccessModeMenu`: `dimmed = fallback === undefined || fallback === mode ? null : "runs as X on <harness>"`. With no fallback, `dimmed` is null, so the approval-required row is NOT dimmed and stays selectable, with no note; it fails only on start. This is a gap: nothing in the menu warns (web: apps/web/src/screens/composer/access-mode-selector.tsx shows `item.dimmed` as a note; desktop apps/desktop/src/renderer/screens/new-thread/access-mode-menu.tsx uses `warning={row.dimmed}`).
- Where an Antigravity thread picks Auto: dimmed note "runs as Auto-accept edits on Antigravity" (spec 06 line ~1075).

## Hooks from the workspace (rec2/hook-default-vartmp.jsonl)
Docs (https://antigravity.google/docs/hooks): workspace `.agents/hooks.json` ("at your project root" for the CLI), global `~/.gemini/config/hooks.json`, plugin `hooks.json`. Format: `{"<name>": {"PreToolUse": [{"matcher":"*","hooks":[{"type":"command","command":"..."}]}]}}`; hook reads JSON on stdin and prints `{"decision":"auto_approve"}` ("Automatically approves the tool call when the default policy would otherwise prompt, while honoring explicit user-configured rules"). Other decisions: allow, deny, ask, force_ask, deny_unless_prior_grant. The hook's cwd is the folder holding hooks.json. Docs say nothing about workspace trust. Binary: "Fixed workspace-local hooks defined in `<workspace>/.agents/hooks.json` not loading after trusting a folder"; trust file strings "workspace trust: failed to write the trust file", "failed to get app data directory for workspace trust store" (trust store is in the app data dir); setting `trustedWorkspaces` (docs).
Test: workspace in /var/tmp with `.agents/hooks.json` (PreToolUse, matcher "*", `sh ./auto.sh`: appends to a marker file outside the workspace, prints auto_approve), `default`, prompt "run echo hi". Result: the hook RAN (marker file written), `run_command` was NOT asked (permission requests: none). Control without hook (mode-default-vartmp-ws.jsonl): run_command asked. No trust prompt, and no trust file appeared in the home, so under `agy acp` a workspace is trusted by default (or trust is not checked). So a repository CAN run code and silence approvals in `default`. `toolPermission: "strict"` was not tested against hooks; docs say auto_approve honors "explicit user-configured rules", and "force_ask"/deny rules exist, so a `permissions.deny/ask` rule or strict is the likely counter, untested.

## TMPDIR follow-ups (TMPDIR=/tmp/hercule-agy-XXXXXX from mkdtemp, workspace under /var/tmp, `default`)
1. A write to `/tmp/hercule-other-1.txt` ASKS; a write to `$TMPDIR/x.txt` does NOT (rec2/tmpdir2-other-vs-tmpdir.jsonl). So with TMPDIR set, only that folder is exempt.
2. A link in the workspace to a folder in the TMPDIR folder, written through (`link/y.txt`): no ask (only the `ln -s` command asked; rec2/tmpdir2-link-into-tmpdir.jsonl). agy resolves links; an agent can create such a link with an approved command, but the approval for the command is the gate, and a link planted by a repository would let writes through unasked ONLY into the private TMPDIR folder, which holds no user data.
3. Resume across processes: process 1 with TMPDIR A wrote `A/num.txt` and was told to remember 4817; A removed; process 2 with TMPDIR B resumed and answered "4817", no stderr, no error (rec2/tmpdir-resume.jsonl).
4. Path lengths. This machine: `/tmp/hercule-agy-XXXXXX` = 23 chars; with `/<20 chars>.sock` (26) = 49, margin 55 to the 104-byte limit. macOS `os.tmpdir()` is typically `/var/folders/xx/<30 chars>/T` = 48 chars (computed); socket path 74, margin 30; resolved `/private/var/folders/...` is 56, socket 82, margin 22. If the adapter uses `/tmp/hercule-agy-XXXXXX` on macOS it resolves to `/private/tmp/hercule-agy-XXXXXX` = 31, socket 57, margin 47 (the short mkdtemp folder is the safer choice there too). Note: on macOS the macOS recording asked for edits in a /tmp workspace, so there the exemption is the system temp dir, not /tmp; whether it follows TMPDIR on macOS is untested.
